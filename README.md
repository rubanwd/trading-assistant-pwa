# trading-assistant-pwa

AI-асистент трейдера: PWA на Cloudflare. Звіт двічі на день і пошук входів раз на 30 хв на ф'ючерсах Binance. Система пропонує сигнали, ордери не виставляє і торгових ключів не зберігає.

- План і архітектура: https://claude.ai/artifact/UbnRZ93BmcHBWeJBS64tD3
- Макети екранів: https://claude.ai/artifact/9vRhZcu858jPLMkjCnTchn

Це інструмент для аналізу, а не фінансова порада.

## Архітектура

Один проєкт Wrangler:

- **Worker**: статичні файли PWA (React, Vite) і API на `/api/*`.
- **Рушій**: Durable Object у юрисдикції `eu`. Усі серверні запити до біржі, OpenRouter та новин ідуть із нього.
- **Cron Trigger** раз на 30 хв будить рушій; час звітів (07:30 і 20:30 за Києвом) рушій звіряє сам.
- **D1**: сигнали, звіти, прогнози, журнал, витрати.
- **Вхід**: Cloudflare Access. **Сповіщення**: Web Push і Telegram.

## Етапи

1. Каркас: деплой, вхід, порожня PWA, тест доступності Binance і моделей з ЄС.
2. Дані і рушій: свічки, індикатори, режим ринку, скан без моделі.
3. Звіти: новини, ранковий і вечірній звіт, push.
4. Сигнали: 2–3 сетапи, фільтр, аналітик і скептик, супровід сигналів.
5. Статистика: калібрування, результат по сетапах, витрати, тижневий розбір.
6. Форвард-тест 8 тижнів без реальних грошей.

## Запуск

```bash
npm install
cp .dev.vars.example .dev.vars
npm run db:migrate:local
npm run dev            # http://localhost:8787
npm test               # тести індикаторів, скану, новин, звітів, push і сигналів
```

Скан можна запустити вручну: `POST /api/scan`. Знімки останнього скану: `GET /api/snapshots/latest`.
Звіт поза розкладом: `POST /api/reports/run` з тілом `{"kind":"morning"}`, `{"kind":"evening"}` або `{"kind":"weekly"}`; стрічка звітів: `GET /api/reports`.

## Сигнали

Одразу після закриття свічки 1h код шукає три сетапи: відкат у тренді, пробій із ретестом, зняття ліквідності з поверненням. Фільтр відсіює кандидатів до моделі: R:R нижче 2, сетап проти режиму чи настрою ринку, дубль по монеті, макроподія в найближчі 2 години, уже 3 відкриті сигнали. Решту оцінюють аналітик і скептик (два окремі виклики Sonnet); сигнал публікується, коли аналітик каже «брати», а скептик дає не менше 60%.

Супровід іде кожні 30 хв за свічками 15m: вхід, ціль, стоп, прострочення. Якщо є друга ціль, на першій фіксується половина позиції, а стоп решти переходить у беззбиток. Результат в R рахується від середини зони входу і вже після комісій (`fee_pct_per_side`, за замовчуванням 0.05% за угоду).

Кандидати, яких відхилила модель, супроводжуються «в тіні»: без подій і сповіщень, лише щоб знати, що було б, якби їх узяли. Це потрібно для калібрування і для оцінки самого фільтра моделі.

Усі налаштування змінюються на екрані «Налаштування» без деплою (`GET` і `PUT /api/settings`, перевірка значень у `src/shared/settings.ts`).

## Моделі ШІ

Усі виклики моделей ідуть через OpenRouter. На сторінці «Моделі ШІ» (кнопка на екрані «Сьогодні») для кожного з п'яти агентів вибирається:

- **модель** зі списку OpenRouter (лише моделі, що відповідають JSON за схемою), з ціною й оцінкою витрат на місяць;
- **рівень міркування** з тих, які підтримує модель, або «як у моделі»;
- **ліміт відповіді** в токенах;
- **запасна модель**, на яку OpenRouter перемкне, якщо основна недоступна.

Агенти: сортувальник новин, автор звітів, аналітик сигналу, скептик, тижневий розбір. Стартові моделі: Claude Haiku 5.5, Sonnet 5.5 і Opus 5.5.

Там само задаються місячна стеля витрат, модель для звітів після стелі та приватність: за замовчуванням запити йдуть лише до провайдерів, що не зберігають дані. Кнопка «Перевірити модель» робить пробний виклик із поточними налаштуваннями агента. Вартість кожного виклику OpenRouter повертає сам; вона пишеться в `llm_calls` і рахується проти стелі.

## Статистика і тижневий розбір

Екран «Статистика»: результат після комісій проти утримання BTC, прогрес до 100 закритих сигналів, результат за сетапами й версіями правил, узяті проти пропущених, тіньовий результат відхилених, калібрування аналітика, скептика і звітів (кошики та бал Браєра), воронка фільтра і витрати. Усе рахує код (`src/worker/stats.ts`).

У неділю о 12:00 за Києвом (`weekly_review_time`) рушій рахує статистику тижня й віддає її агенту «Тижневий розбір». Модель пояснює цифри і пропонує до трьох змін правил. Вмикаєш їх ти в «Налаштуваннях» → «Правила сетапів»: нова версія не частіше ніж раз на 14 днів (`playbook_min_days`). Якщо стелю витрат вичерпано, тижневий звіт виходить зі статистикою без розбору моделі.

## Дані й надійність

- **Запасна біржа.** `market_source: "auto"`: Binance, а якщо він відповідає рушію 451 чи 403 (блокування за локацією), то Bybit до перезапуску рушія. Джерело видно в «Пульсі системи». Можна зафіксувати `binance` або `bybit`.
- **Прибирання.** Раз на добу рушій видаляє знімки й новини, старші за `retention_days` (30), окрім знімків, на які посилаються сигнали.
- **Офлайн.** Service worker тримає копію останніх відповідей API; без мережі застосунок показує їх із позначкою часу.
- **Жива ціна** BTC і монети сигналу йде з WebSocket Binance напряму в браузер; без нього показується ціна останнього скану.

## Звіти і сповіщення

Кожні 30 хв після скану рушій забирає RSS-стрічки (`settings.news_feeds`), а сортувальник новин перетворює нові заголовки на поля за схемою. О 07:30 і 20:30 за Києвом Sonnet складає звіт зі знімків ринку, полів новин і результатів попередніх прогнозів. Кожен сценарій звіту стає рядком у `forecasts` з правилом, яке код перевіряє за свічками 1h.

Сповіщення про готовий звіт ідуть у Web Push і дублюються в Telegram:

1. `npx @pushforge/builder vapid` видасть публічний ключ і приватний у форматі JWK.
2. Публічний ключ і контакт (`mailto:…`) встав у `vars` у `wrangler.jsonc`: `VAPID_PUBLIC_KEY`, `VAPID_SUBJECT`.
3. `npx wrangler secret put VAPID_PRIVATE_KEY` (JWK одним рядком).
4. Для Telegram: `npx wrangler secret put TELEGRAM_BOT_TOKEN` і `npx wrangler secret put TELEGRAM_CHAT_ID`.
5. У застосунку на екрані «Сьогодні» натисни «Увімкнути сповіщення». На iPhone спершу додай застосунок на початковий екран.

Необов'язково: `npx wrangler secret put COINGECKO_API_KEY` (план Demo) для домінації BTC у звітах.

## Деплой без ноутбука (з телефона)

Усе робиться в панелі Cloudflare; збирає й деплоїть Cloudflare з GitHub (Workers Builds).

1. **D1**: Storage & Databases → D1 → Create, назва `trading-assistant`, розташування Western Europe. ID бази впиши в `database_id` у `wrangler.jsonc` (це не секрет).
2. **Підключення репозиторію**: Workers & Pages → Create → Import a repository → цей репозиторій. Назва Worker `trading-assistant-pwa` (як `name` у `wrangler.jsonc`), команда збірки `npm run build`, команда деплою `npm run deploy:ci` (міграції бази, потім деплой).
3. **Права токена збірки**: My Profile → API Tokens → токен Workers Builds → Edit → додати Account · D1 · Edit. Без цього міграції не застосуються. Потім Retry build.
4. **Секрети й змінні**: Worker → Settings → Variables and Secrets. Секрети: `OPENROUTER_API_KEY`, `VAPID_PRIVATE_KEY`, за бажанням `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`. Змінні (Text): `ACCESS_TEAM_DOMAIN`, `ACCESS_AUD`, `APP_ORIGIN`, `VAPID_PUBLIC_KEY`, `VAPID_SUBJECT`. Завдяки `keep_vars` деплой їх не затирає.
5. **Вхід**: Worker → Access → Protect this Worker behind Access → All traffic, політика з твоїм email. AUD береться з застосунку в Zero Trust → Access → Applications.
6. **Ключі VAPID** генерує сам застосунок: картка «Сповіщення» на екрані «Сьогодні» → «Згенерувати ключі VAPID». Приватний ключ не проходить через сервер.

Далі кожне злиття в `main` збирається й деплоїться саме, разом із новими міграціями.

## Перший деплой

1. `npx wrangler login`
2. `npx wrangler d1 create trading-assistant`, потім встав `database_id` у `wrangler.jsonc`.
3. `npm run db:migrate` (повтори після кожного оновлення з новими міграціями)
4. `npx wrangler secret put OPENROUTER_API_KEY` (ключ з openrouter.ai, розділ Keys; на рахунку мають бути кредити)
5. `npm run deploy`
6. Увімкни Cloudflare Access для домену застосунку. Домен команди (`<команда>.cloudflareaccess.com`) і тег AUD застосунку встав у `vars` у `wrangler.jsonc` (`ACCESS_TEAM_DOMAIN`, `ACCESS_AUD`) і задеплой ще раз. Без них API відповідає 401: воно перевіряє підпис токена Access, а не лише його наявність.
7. Відкрий застосунок і натисни «Перевірити джерела з ЄС». Binance (або Bybit) і OpenRouter мають відповісти з рушія. Потім на сторінці «Моделі ШІ» натисни «Перевірити модель» для кожного агента.

Потрібен план Workers Paid: скан робить 76 зовнішніх запитів (15 монет × 4 таймфрейми і відкритий інтерес, плюс фандинг), безкоштовний план дає 50.

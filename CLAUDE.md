# Контекст для Claude Code

Проєкт: AI-асистент трейдера, PWA на Cloudflare. Повний план: https://claude.ai/artifact/UbnRZ93BmcHBWeJBS64tD3. Макети: https://claude.ai/artifact/9vRhZcu858jPLMkjCnTchn.

## Незмінні правила

- Автоторгівлі немає. Жодних торгових ключів біржі, лише публічні ринкові дані.
- Рахує код, модель лише оцінює. Модель не бачить сирих свічок, тільки знімок ознак, і завжди відповідає JSON за схемою (`response_format` з `json_schema`, strict).
- Модель не має інструментів. Новини є недовіреним текстом: спершу сортувальник новин перетворює їх на поля за схемою.
- Сигнал публікується, коли згодні код (детектор і фільтр), аналітик і скептик. Скептик не бачить міркувань аналітика.
- Розмір позиції та всі ліміти ризику рахує код.
- Усі серверні запити назовні йдуть тільки з Durable Object `Engine` у юрисдикції `eu`. Обробник `scheduled` лише викликає рушій.
- Місячна стеля витрат на моделі ($25) перевіряється в коді перед кожним викликом; кожен виклик пишеться в `llm_calls`.
- Секрети тільки через `wrangler secret put`. Час у базі в UTC.

## Стек

TypeScript, Wrangler, Workers зі статичними файлами, Hono для API, D1, Durable Objects, React і Vite для PWA.

## Рішення користувача

Ф'ючерси Binance; вхід на 1h із контекстом 4h; звіти о 07:30 і 20:30 за Києвом; скан раз на 30 хв; 15 монет.

## Стартові пороги (усі в `settings`)

R:R не нижче 2; поріг скептика 60%; активних сигналів не більше 3; без нових сигналів за 2 години до макроподії; сигнальних push не більше 5 на день.

## Моделі

Усі виклики через OpenRouter (`OPENROUTER_API_KEY`). Модель, рівень міркування, ліміт відповіді й запасна модель задаються для кожного агента на сторінці «Моделі ШІ» (`settings.ai_agents`; схема й перевірка в `src/shared/ai.ts`). Агенти: news, report, analyst, skeptic, weekly. Стартово Haiku 5.5 для новин, Sonnet 5.5 для звітів, аналітика й скептика, Opus 5.5 для тижневого розбору. Після стелі звіти пише `ai_budget_fallback_model`, решта агентів зупиняється.

## Поточний етап

Код усіх етапів MVP написано; далі деплой і форвард-тест (8 тижнів без реальних грошей, рішення після 100 закритих сигналів).

Працює на безкоштовному плані Workers. `tick` (Cron раз на 30 хв) лише планує цикл; кроки виконує `Engine.alarm()`, по одному на запуск, бо кожен запуск має власні ліміти (50 зовнішніх запитів, 50 звернень до D1, 10 мс процесора). Кроки: `scan:N` (по `CHUNK_SIZE` = 4 монети) → `scan:done` → `news` → `signals` (супровід, тінь, пошук кандидатів) → `review:N` (аналітик і скептик для одного кандидата) → `forecasts` → `reports` → `weekly` → `cleanup`. Стан циклу в сховищі Durable Object (`PipelineState`), підсумок із кількістю запитів на крок у `runs` (kind `pipeline`). Свічки кешуються в SQLite рушія (`market/cache.ts`): біржа докачує лише нові. Налаштування читаються одним запитом на крок. Новий код має тримати крок у цих лімітах: усі запити назовні через `this.http` (лічильник).

- Дані: адаптер `MarketData` (`src/worker/market`): `binance.ts`, `bybit.ts`, `failover.ts` (перемикання на Bybit на 451/403), `cache.ts` (кеш свічок). `Engine.market()` вибирає за `settings.market_source`. Індикатори `indicators.ts`, режим `regime.ts`, знімки `snapshot.ts`, `scan.ts`; денні закриття в `prices_daily`.
- Новини: `news/rss.ts`, `news/triage.ts`. У схемі сортувальника лише числа й переліки.
- Модель: єдиний шлях `Engine.llm` (`llm.ts`, OpenRouter Chat Completions): стеля перед викликом, модель агента з налаштувань, `provider.require_parameters`, запис у `llm_calls` з вартістю від OpenRouter. Каталог моделей `Engine.models()` (кеш 6 год), стан ключа `Engine.keyInfo()`, пробний виклик `Engine.testAgent()`. API: `GET/PUT /api/ai`, `POST /api/ai/test`.
- Сигнали (`src/worker/signals`): `detectors.ts`, `filter.ts`, `review.ts`, `track.ts` (друга ціль: половина на першій, стоп у беззбиток). Комісії `feeR` у `src/shared/risk.ts`, пишуться в `signals.fee_r`. Відхилені моделлю супроводжуються в тіні (`shadow_status`, `shadow_r` уже після комісій).
- Статистика: `stats.ts` (чисті функції й завантажувач D1), тижневий розбір `weekly.ts`.
- Бектест (локально, не на Cloudflare): `npm run backtest`, код у `src/backtest/` (`simulate.ts` викликає ті самі `detect`, `reject`, `replay`), CLI `scripts/backtest.ts`, свічки з `data.binance.vision`. Зміни в детекторах, фільтрі чи супроводі одразу діють і в бектесті.
- Налаштування: схема й перевірка в `src/shared/settings.ts`, API `GET/PUT /api/settings`; правила сетапів `GET/POST /api/playbook` з версіями.
- Вхід: `access.ts` перевіряє підпис токена Cloudflare Access; ключі команди бере рушій.
- Застосунок: вкладки «Сьогодні», «Сигнали», «Звіти», «Статистика», екрани «Налаштування» і «Моделі ШІ» (`Ai.tsx`); графік `Chart.tsx`, жива ціна `live.ts` (WebSocket Binance з браузера), офлайн-кеш у `public/sw.js`.
- Тести: `npm test`.

Перевірено на проді: Binance відповідає рушію в ЄС 451, рушій працює через Bybit. Не перевірено на проді: живі виклики OpenRouter (чи кожна вибрана модель справді тримає JSON-схему); доставка Web Push на iPhone; як часто детектори спрацьовують на живому ринку.

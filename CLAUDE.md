# Контекст для Claude Code

Проєкт: AI-асистент трейдера, PWA на Cloudflare. Повний план: https://claude.ai/artifact/UbnRZ93BmcHBWeJBS64tD3. Макети: https://claude.ai/artifact/9vRhZcu858jPLMkjCnTchn.

## Незмінні правила

- Автоторгівлі немає. Жодних торгових ключів біржі, лише публічні ринкові дані.
- Рахує код, модель лише оцінює. Модель не бачить сирих свічок, тільки знімок ознак, і завжди відповідає JSON за схемою (`output_config.format`).
- Модель не має інструментів. Новини є недовіреним текстом: спершу Haiku перетворює їх на поля за схемою.
- Сигнал публікується, коли згодні код (детектор і фільтр), аналітик і скептик. Скептик не бачить міркувань аналітика.
- Розмір позиції та всі ліміти ризику рахує код.
- Усі серверні запити назовні йдуть тільки з Durable Object `Engine` у юрисдикції `eu`. Обробник `scheduled` лише викликає рушій.
- Місячна стеля витрат на моделі ($25) перевіряється в коді перед кожним викликом; кожен виклик пишеться в `llm_calls`.
- Секрети тільки через `wrangler secret put`. Час у базі в UTC.

## Стек

TypeScript, Wrangler, Workers зі статичними файлами, Hono для API, D1, Durable Objects, React і Vite для PWA.

## Рішення користувача

Ф'ючерси Binance; вхід на 1h із контекстом 4h; звіти о 07:30 і 20:30 за Києвом; скан раз на 30 хв; 15 монет.

## Стартові пороги (усі в `settings`)

R:R не нижче 2; поріг скептика 60%; активних сигналів не більше 3; без нових сигналів за 2 години до макроподії; сигнальних push не більше 5 на день.

## Моделі

Haiku 5.5 для новин, Sonnet 5.5 для звітів і перевірки сигналів, Opus 5.5 через Batch API для тижневого розбору.

## Поточний етап

Сигнали. Кожен `tick` рушія: скан → новини → сигнали (супровід і пошук) → закриття прогнозів → звіт, якщо настав час.

- Дані: `Engine.runScan` бере дані через адаптер `MarketData` (`src/worker/market`), рахує індикатори (`indicators.ts`), режим ринку (`regime.ts`) і пише знімки в `snapshots` (`snapshot.ts`, `scan.ts`). Свічки скану живуть у пам'яті рушія для детекторів і супроводу.
- Новини: `news/rss.ts` розбирає стрічки з `settings.news_feeds`, `news/triage.ts` задає схему сортувальника. У схемі лише числа й переліки: вільний текст із заголовка далі не йде.
- Модель: єдиний шлях `Engine.llm` (`llm.ts`): стеля перед викликом, запис у `llm_calls`, SDK `@anthropic-ai/sdk`. Після стелі звіти пише Haiku; сортування новин і перевірка сигналів зупиняються.
- Сигнали (`src/worker/signals`): `detectors.ts` (три сетапи; шорт рахується на дзеркальних цінах), `filter.ts` (відсів до моделі), `review.ts` (правила сетапів, аналітик, скептик, рішення), `track.ts` (стан сигналу відтворюється зі свічок 15m). Сетапи шукаються лише на свіжій свічці 1h. Відхилені моделлю кандидати лягають у `signals` зі статусом `rejected`.
- Ризик: `src/shared/risk.ts`, спільний для рушія і застосунку.
- Звіти: `report/input.ts` складає вхід, `report/schema.ts` задає схему й перевіряє відповідь кодом. Сценарії стають рядками `forecasts`; закриває їх `forecasts.ts` за свічками 1h.
- Сповіщення: `push.ts` (Web Push через `@pushforge/builder`, Telegram), надсилає рушій. Для сигналів діють тихі години й денний ліміт (`Engine.signalPush`).
- Час: `time.ts`, київський час рахує код.
- Тести: `npm test`.

Не перевірено на проді: чи відповідає `fapi.binance.com` рушію в ЄС; живий виклик Claude API; доставка Web Push на iPhone; як часто детектори спрацьовують на живому ринку. Якщо Binance відповідає 451, додати запасну біржу за адаптером `MarketData` і підставити її в `Engine.market()`.

# Контекст для Claude Code

Проєкт: AI-асистент трейдера, PWA на Cloudflare. Повний план: https://claude.ai/artifact/UbnRZ93BmcHBWeJBS64tD3. Макети: https://claude.ai/artifact/9vRhZcu858jPLMkjCnTchn.

## Незмінні правила

- Автоторгівлі немає. Жодних торгових ключів біржі, лише публічні ринкові дані.
- Рахує код, модель лише оцінює. Модель не бачить сирих свічок, тільки знімок ознак, і завжди відповідає JSON за схемою (`output_config.format`).
- Модель не має інструментів. Новини є недовіреним текстом: спершу Haiku перетворює їх на поля за схемою.
- Сигнал публікується, коли згодні код (детектор і фільтр), аналітик і скептик. Скептик не бачить міркувань аналітика.
- Розмір позиції та всі ліміти ризику рахує код.
- Усі серверні запити назовні йдуть тільки з Durable Object `Engine` у юрисдикції `eu`. Обробник `scheduled` лише викликає рушій.
- Місячна стеля витрат на моделі ($25) перевіряється в коді перед кожним викликом; кожен виклик пишеться в `llm_calls`.
- Секрети тільки через `wrangler secret put`. Час у базі в UTC.

## Стек

TypeScript, Wrangler, Workers зі статичними файлами, Hono для API, D1, Durable Objects, React і Vite для PWA.

## Рішення користувача

Ф'ючерси Binance; вхід на 1h із контекстом 4h; звіти о 07:30 і 20:30 за Києвом; скан раз на 30 хв; 15 монет.

## Стартові пороги (усі в `settings`)

R:R не нижче 2; поріг скептика 60%; активних сигналів не більше 3; без нових сигналів за 2 години до макроподії; сигнальних push не більше 5 на день.

## Моделі

Haiku 5.5 для новин, Sonnet 5.5 для звітів і перевірки сигналів, Opus 5.5 через Batch API для тижневого розбору.

## Поточний етап

Код усіх етапів MVP написано; далі деплой і форвард-тест (8 тижнів без реальних грошей, рішення після 100 закритих сигналів).

Кожен `tick` рушія: скан → новини → сигнали (супровід, тіньовий супровід відхилених, пошук) → закриття прогнозів → звіт, якщо настав час → тижневий розбір (відправка й забір пакета) → прибирання раз на добу.

- Дані: адаптер `MarketData` (`src/worker/market`): `binance.ts`, `bybit.ts`, `failover.ts` (перемикання на Bybit на 451/403). `Engine.market()` вибирає за `settings.market_source`. Індикатори `indicators.ts`, режим `regime.ts`, знімки `snapshot.ts`, `scan.ts`; денні закриття в `prices_daily`.
- Новини: `news/rss.ts`, `news/triage.ts`. У схемі сортувальника лише числа й переліки.
- Модель: єдиний шлях `Engine.llm` (`llm.ts`) для звичайних викликів; тижневий розбір іде через `BatchTransport` (Message Batches API, −50%), стеля перевіряється перед відправкою, виклик пишеться в `llm_calls` при заборі результату.
- Сигнали (`src/worker/signals`): `detectors.ts`, `filter.ts`, `review.ts`, `track.ts` (друга ціль: половина на першій, стоп у беззбиток). Комісії `feeR` у `src/shared/risk.ts`, пишуться в `signals.fee_r`. Відхилені моделлю супроводжуються в тіні (`shadow_status`, `shadow_r` уже після комісій).
- Статистика: `stats.ts` (чисті функції й завантажувач D1), тижневий розбір `weekly.ts`.
- Налаштування: схема й перевірка в `src/shared/settings.ts`, API `GET/PUT /api/settings`; правила сетапів `GET/POST /api/playbook` з версіями.
- Вхід: `access.ts` перевіряє підпис токена Cloudflare Access; ключі команди бере рушій.
- Застосунок: вкладки «Сьогодні», «Сигнали», «Звіти», «Статистика» і екран «Налаштування»; графік `Chart.tsx`, жива ціна `live.ts` (WebSocket Binance з браузера), офлайн-кеш у `public/sw.js`.
- Тести: `npm test`.

Не перевірено на проді: Binance і Bybit з рушія в ЄС; живі виклики Claude API і Batch API; доставка Web Push на iPhone; як часто детектори спрацьовують на живому ринку.
